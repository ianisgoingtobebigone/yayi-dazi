# 知识生命周期与版本治理

状态：适用于`0.9.0-portfolio`作品集候选包，不代表知识已经完成专业或临床验证。

## 1. 唯一登记入口

M10的31个来源继续保存在`runtime-data/m10_catalog.json`的`source_registry`中；M00安全来源和数据治理依据登记在[知识维护登记](knowledge-maintenance-register.json)。不得再创建第三套平行来源目录。

执行维护审计时，同时读取两处登记，检查来源编号、权利范围、最近复核日期、下次复核日期和影响模块。来源网页能够打开只表示可访问，不代表医学内容、法律结论或专业适用性已经验证。

## 2. 复核周期

| 内容 | 工程复核周期 |
|---|---:|
| M00安全分流、中国指南和专业标准 | 90天 |
| 一般知识目录 | 180天 |
| 锁定版教材新版检查 | 365天 |
| 隐私、人工智能与医疗监管依据 | 90天 |
| 正式文献推荐的元数据与撤稿状态 | 30天内 |

以上是工程维护间隔，不是医学有效期。每次正式发布仍需运行完整审计；发现新版、撤回、来源冲突、用户纠错或规则异常时立即提前复核。

## 3. 到期动作

- 教材到期：要求检查新版；检查完成前保留既有版次说明，但不得宣称内容为最新版。
- 指南或安全来源到期：暂停受影响规则的新版本发布和最新性声明；必要时把相关候选变更隔离。
- `verify_before_use`来源到期：暂停该来源进入运行检索。
- 文献元数据超过30天或撤稿状态未知：不生成正式文献推荐。
- 监管依据到期：继续保持公众真实数据和医疗服务发布关闭，完成复核后再决定。

审计程序只读取本地登记并报告到期状态，不访问网络、不自动更新医学规则，也不自动把来源重新标记为已审核。

## 4. 变更流程

```text
发现来源变化
→ 登记原版本与候选版本差异
→ 标记受影响模块和主张
→ 在候选目录修改
→ 添加最低数量的针对性案例
→ 运行模块测试、全库测试和知识审计
→ 用户审核
→ 生成新的知识快照和发布清单
```

任何候选修改都不能直接覆盖已安装版本。安全、治疗边界或医学主张变化在缺少专业人员审核时，只能作为内部候选，不得标记为专业审核通过。

## 5. 最低增量测试

- 安全规则：至少6例，包括明确命中2例、近似否定2例、含糊1例和用户纠正1例。
- 专业路由：至少4例，包括正确路由2例和易混淆路由2例。
- 知识条目：至少3个查询，包括直接表达、同义表达和应无结果各1个。
- 输出或隐私规则：至少2例，包括允许和阻断各1例。

最低数量只用于防止无测试变更，不能替代专业验证。

## 6. 版本规则

同时维护四个版本：完整Skill发布版本、安全规则版本、知识快照版本和评测集版本。

- 主版本：不兼容的数据契约、能力边界或输出结构变化。
- 次版本：新增审核后的能力、规则或知识范围。
- 修订版本：不改变行为的文字、来源元数据或错误修复。

当前候选为`0.9.0-portfolio`。`1.0.0`只有在完成独立专业验证和相应发布条件后才能另行审核，不因自动测试通过而自动升级。

## 7. 发布边界

知识审计通过只允许形成作品集候选包。个人安装和远程GitHub推送分别需要用户明确授权；临床生产、公众真实医疗数据处理和临床有效性声明继续保持关闭。
