# M11主Agent编排契约

状态：M11-01至M11-07已整体实现并通过规则与回归审核；作品集级文本前向工程验证已完成，外部专业验证及真实图像验证未完成，`production_enabled=false`。

## 1. 职责

M11负责跨轮状态、事实账本、问题历史、业务路由、模块调度、基础模型输入、自适应输出计划、主张来源审查、失败降级及输出前复核。`state_machine.current_state`是主Agent执行的统一状态，M00的`next_state`继续作为安全子状态保留。M11不重新计算M00等级，不替代基础模型生成语言，也不把检索相似度变成疾病判断。

## 2. 模块重要性

| 模块 | 重要性 | 调用规则 |
|---|---|---|
| M00 | 安全关键 | 每轮新信息前置执行，发送前再次执行；不得绕过 |
| M01 | 事实完整性关键 | 保存原话、来源、时间、否认、未知、历史和纠正；不负责路由 |
| M02-M07 | 专业核心 | 一个主模块，必要时一个交叉模块 |
| M08 | 条件安全关键 | 仅有具体照片任务时调用；新增图像事实必须返回M00 |
| M09 | 条件边界敏感 | 仅N1/S0且用户明确索要治疗背景时调用 |
| M10 | 证据核心 | 只按已记录事实检索；文献推荐是条件子任务 |
| M11 | 编排与完整性关键 | 保持风险下限、约束模块与模型、审查最终草稿 |
| M12 | 发布关键 | 不参与普通问诊；决定能否开放生产输出 |

## 3. 路由

- 路由候选由基础模型根据用户原话提出，M11只验证和排序。
- `relevance_score_0_to_100`是0至100的业务路由工程分，不是医学置信度。
- 前两候选分差不超过5.0且没有明确交叉模块需要时，只问一次改变分道的问题。
- 交叉模块须达到60.0以上，且一次最多一个。
- 健康与美观并存时`health_first=true`；健康模块为主，M06最多为交叉模块。
- M08、M09、M10不是专业主路由所有者。
- M10只接受`route_status=confirmed`的当前路由；每次调用必须明确由主模块或次模块中的哪一个发起，禁止附加第三个检索模块。
- 跨模块证据检索必须按主模块和次模块拆成隔离请求；同一任务与模块的重复M10请求会被拒绝。
- 分道澄清在同一问题中最多一次；仍不确定时保留`route_unresolved`，不反复询问，也不默认选择疾病方向。
- 只有分道问题真正发出后才设置`route_clarification_used=true`；仅进入等待状态不消耗机会。
- 用户纠正必须同时保留原事实和纠正事实，并交回M00进行有记录的纠错重算。

## 4. 固定执行顺序

```text
新信息 → M00 → M01 → M11业务路由 → M02-M07
      → 条件M08 → 图像新事实返回M00
      → M10 → 条件M09 → 基础模型草稿
      → M11事实/来源/边界复核 → M00 final_guard
```

E0/E1停止普通模块；U1先显示M00行动并最多问一个改变去向的问题；`NEEDS_CLARIFICATION`只执行M00澄清。

M08一旦返回新的候选图像事实，M11立即暂停M09、M10和基础模型草稿，状态改为`waiting_for_m00_image_recheck`。只有取得新一轮M00结果后，才能恢复后续模块。M10先于M09执行，避免治疗背景脱离已审核证据。

M02至M07若在结构化事实后明确返回新的安全事实组合，M11同样暂停后续模块并进入`waiting_for_m00_structured_fact_recheck`。单个专业字段编号不得自动触发该状态，必须有用户原话依据和模块显式提交。

M10返回检索缺口时，M11不得要求其扩大到全库或未授权模块。M11可以保留`retrieval_gap`，或将基础模型已有知识明确标记为`model_prior`；不得伪装成教材或检索来源。

## 5. 基础模型与主张来源

基础模型必须提交`text`、`claims`及`presentation`。`presentation`按本轮计划提交开头行动、审核后问题、智慧口腔记录栏目和一句能力边界；不得自行补齐未选择的栏目。每项主张使用以下来源类型之一：

- `user_fact`：必须回到M01-M08字段；
- `retrieved_evidence`：必须有来源及与用户事实的显式关系；
- `model_prior`：不得伪装成教材或指南；
- `runtime_inference`：必须说明不确定性；
- `offline_required`：明确只能由线下检查确认。

证据关系只允许`supports`、`conflicts`、`missing_clinician_evidence`、`context_only`或`retrieval_gap`，不得由相似度自动决定。

## 6. 问询与智慧口腔记录

- M11保存问题编号和目标事实，阻止同一问题或同一事实被重复询问。
- 普通问诊一轮最多一个问题块，优先包含二至三个紧密相关的信息点且不得超过三个；同一问题最多两轮普通问题块。
- 两轮后不再为填满字段继续追问，必须基于已有信息生成记录，并把真正影响下一步的缺失项写为不确定性。
- E0/E1只给紧急行动；M00澄清和路由澄清各只问一个问题；U1先给行动，问题不得延迟行动。
- 智慧口腔记录只在普通流程展示，包含四个核心栏目和最多两个由当前状态选择的条件栏目；空栏目不得出现。
- M11同时返回移动端、电脑端和纯文字回退三种渲染配置。渲染端只改变版面，不得改变事实、紧迫度、专业路由或栏目选择。
- 治疗背景与文献推荐只按用户请求展示，并位于智慧口腔记录之外。
- 输出使用专业、亲和、克制的中文，禁止卖萌称呼、表情符号、无关延伸和固定五段堆叠。
- 用户纠正、M08图像事实或专业模块新增安全事实会进入独立的M00复核等待状态；复核完成前不得追问、调用后续模块或生成记录。
- 每轮记录`from_state`、`to_state`和转移原因，便于审核跨轮行为。

完整展示规则见[用户问询与智慧口腔记录契约](user-experience-and-output.md)。

## 7. 失败和输出门禁

- 合同错误不重试；非合同型瞬时错误最多重试一次。
- 失败只降低功能可用性，不降低M00风险等级，不补造诊断，不默认S0。
- M11拦截确定诊断、个体治疗选择、药物剂量疗程、操作步骤、普通照片确诊、疾病置信百分比、内部编号、本地路径、个人电话和境外服务入口。
- M11同时拦截未批准问题、重复追问、空栏目、未选择栏目、超过两个条件栏目、卖萌表达和超长输出。
- M11通过后仍须M00执行`final_guard`；在专业参考标准、真实图像和发布门禁完成前，公共生产输出保持禁用。
