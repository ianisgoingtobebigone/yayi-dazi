# 主Agent安全状态机（节点审核稿）

状态：安全状态约束已审核；M11运行代码已于2026-08-13接入。M12完成前生产禁用。

## 1. 状态变量

- `candidate_level`：本轮新信息单独匹配出的候选等级。
- `risk_floor_level`：本次口腔问题中已经确认过的最高安全等级。
- `effective_level`：主Agent本轮必须执行的等级，取`candidate_level`和`risk_floor_level`中更紧急者。
- `clarification_used`：本个含糊危险信号是否已经使用过一次澄清机会。
- `episode_id`：本次问题的临时编号，仅用于区分同一会话里的不同问题，不包含身份信息。

等级顺序固定为：`E0 > E1 > U1 > N1 > S0`。`NEEDS_CLARIFICATION`是过渡状态，不参与等级排序。

## 2. 主状态

| 状态 | 含义 | 允许动作 |
|---|---|---|
| `START` | 尚未处理本轮用户信息 | 进入前置识别 |
| `PRE_GATE` | 识别口腔健康、美观、混合或非口腔意图 | 选择完整分流、美观简筛或跳过 |
| `CLARIFY_ONCE` | 一个危险表达含糊，且一次直接追问可改变去向 | 只问一个判断问题 |
| `AESTHETIC_MINI_SCREEN` | 明确偏美观，但仍需排除健康与功能问题 | 使用一条合并式安全筛查 |
| `E0_HALT` | 立即医疗急诊 | 展示急诊去向并停止普通问诊 |
| `E1_ROUTE` | 紧急牙科处理 | 先展示去向，只补不延误就医的信息 |
| `U1_LIMITED` | 目标24小时内评估 | 立即告知时效，最多再问一个会改变去向的问题 |
| `N1_INTAKE` | 2至7天内面诊 | 完成压缩问诊和就诊建议 |
| `S0_OBSERVE` | 有限观察 | 给观察边界和升级条件 |
| `FINAL_GUARD` | 输出最终建议前复核 | 比较历史风险下限与本轮候选等级 |
| `END` | 本轮安全动作已经完成 | 等待新信息；新信息出现时重新进入`PRE_GATE` |

## 3. 前置转移逻辑

| 当前状态 | 条件 | 下一状态 |
|---|---|---|
| `START` | 用户信息涉及牙齿、牙龈、口腔、颌面、咬合、正畸或面部美观 | `PRE_GATE` |
| `PRE_GATE` | 出现任何硬危险信号 | 立即运行完整分流，并进入对应的`E0_HALT`、`E1_ROUTE`或`U1_LIMITED` |
| `PRE_GATE` | 明确存在疼痛、敏感、肿胀、出血、黏膜破损、外伤、发热、异常分泌、牙齿松动或折裂、治疗后异常，或张口、咀嚼、吞咽、说话功能异常 | 运行完整分流 |
| `PRE_GATE` | 健康与美观信息同时存在 | 运行完整分流，之后才允许进入美观问诊 |
| `PRE_GATE` | 只有排列、拥挤、间隙、前突、中线、笑线、牙色、牙形或长期稳定的面部不对称，且没有健康或功能线索 | `AESTHETIC_MINI_SCREEN` |
| `PRE_GATE` | 意图或危险信号含糊 | `CLARIFY_ONCE` |
| `AESTHETIC_MINI_SCREEN` | 明确没有疼痛、肿胀、出血、外伤、发热及功能异常；面部不对称长期稳定 | 返回主Agent的美观问诊 |
| `AESTHETIC_MINI_SCREEN` | 任一健康或功能项为“是”，或不对称近期新出现、突然加重 | 运行完整分流 |
| `CLARIFY_ONCE` | 用户确认危险信号 | 进入对应安全等级 |
| `CLARIFY_ONCE` | 用户明确否认且没有其他危险信号 | 按其余已知事实继续分流 |
| `CLARIFY_ONCE` | 仍为不确定，但原始表述构成可信高风险 | 采用更保守等级 |

美观简筛使用一条合并问题，不展开完整牙痛问诊：

> 在讨论牙齿排列或面部美观前，请确认目前有没有疼痛、肿胀、出血、外伤、发热，或者张口、咀嚼、吞咽异常？如果是面部不对称，它是近期新出现或突然加重的吗？

## 4. 禁止降级的状态约束

每次得到有效候选等级后执行：

```text
risk_floor_level = 更紧急者(risk_floor_level, candidate_level)
effective_level  = 更紧急者(risk_floor_level, candidate_level)
```

因此，普通状态转移中不存在`E0→E1/U1/N1/S0`、`E1→U1/N1/S0`或`U1→N1/S0`。具体约束如下：

1. 主Agent不得用“后来疼痛轻了”“照片看着不严重”或另一个子模块的低风险结果覆盖已经确认的高等级。
2. 多个模块同时返回结果时，按最高安全等级执行，不做平均、投票或总分抵消。
3. `E0_HALT`和`E1_ROUTE`对普通问诊是中止状态；不能为了收集完整病史、照片或美观信息返回普通流程。
4. `U1_LIMITED`只允许补问一个会改变就医目的地的问题，不能退回完整4至6轮问诊。
5. 图像只能触发升级、文本澄清或“不足以判断”，不能直接降低`risk_floor_level`。

## 5. 用户纠正原话时如何处理

用户可能明确说明自己此前打错字或表达错误。此时主Agent仍不得直接降级，只能提交`correction_event`给安全分流模块：

- 同时保留原始表述和纠正表述；
- 只追问一次与该纠正有关的核心问题；
- 在纠正确认前继续执行较高等级；
- 只有安全分流模块可以返回重新计算结果，并记录`correction_reason`；
- 该过程属于“纠错重算”，不是主Agent的普通降级转移。

## 6. 新信息与最终复核

- 用户每补充一条新信息，主Agent先回到`PRE_GATE`重新检查，再继续当前问诊。
- 新候选等级更高时，立即升级并更新`risk_floor_level`。
- 新候选等级更低时，保留原等级。
- 输出最终建议前必须进入`FINAL_GUARD`；若文案中的时效或去向低于`effective_level`，禁止发送并重新生成。
- M08产生任何新候选图像事实时，后续专业、证据、治疗背景和生成流程暂停，先回到`PRE_GATE`取得新的M00结果。
- 分道澄清与M00危险信号澄清分别记账，但每类在同一问题中都只允许一次；仍不确定时保留不确定性并采用通用口腔专业评估去向。

## 7. 可审核示例

| 用户信息 | 状态路径 | 结果 |
|---|---|---|
| “牙齿不齐，想改善笑容” | `START→PRE_GATE→AESTHETIC_MINI_SCREEN` | 简筛全部为否后返回美观问诊 |
| “脸这两天突然歪了，好像有点肿” | `START→PRE_GATE→完整分流` | 不按纯美观处理 |
| “牙痛，还有点咽不下去” | `START→PRE_GATE→CLARIFY_ONCE` | 确认吞咽困难则进入`E0_HALT` |
| 已进入`U1_LIMITED`，随后用户说“现在没那么痛了” | `U1_LIMITED→PRE_GATE→FINAL_GUARD` | 保留U1，不降为N1或S0 |

## 8. 本节点审核项

1. 是否接受“硬危险信号覆盖所有分数”的前置逻辑。
2. 是否接受`risk_floor_level`在同一次问题中单调不下降。
3. 是否接受E0/E1为普通问诊中止状态、U1最多再问一个改变去向的问题。
4. 是否接受用户纠正原话时只能由安全模块执行有记录的纠错重算。
